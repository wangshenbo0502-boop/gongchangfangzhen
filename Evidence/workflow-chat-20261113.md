# 工单流程、助手与拆装清晰度验证

日期为 2026-11-13，Asia/Shanghai。Windows 主程序使用 Unity 6000.3.8f1 构建，场景为 WorkshopDemo.unity 和原小车装配训练。

- 从设备工作区可以直达故障学习。开始实训进入对应工单，点击“开始巡检”派出小车。途中通过“查看现场”和“返回工单”往返，到场后只填写故障原因。设备名称由工单带入。提交维修后点“验收通过”归档，驳回回到待巡检。
- “AI 助手”和“更多”移到左侧。聊天页采用单列对话、底部输入、快捷提问和可展开引用，顶部显示选中设备及工单阶段。服务使用设备名称、型号、故障和进度构建检索词，更新工单说明并新增四类设备现象对照。
- 监控界面用不透明底色覆盖相机视口之外的区域。两次从小车装配返回后均核对监控相机边界，截图中未见原装配画面残留。
- 系统内设备观察按视口实际像素的 1.5 倍渲染，限制在 3840×2160 内并维持 4 倍 MSAA。隐藏的故障近景相机暂停渲染。实测水泵和风机在 720p 拆装视口使用 1872×896，1080p 使用 2808×1344。独立展示器有自己的灯光和锐化，未测两者的帧率或做逐像素对比。

720p 和 1080p 的 Windows 检查版各通过 215 项，覆盖可见控件射线、设备拆装、有限元查看、工单实际寻路到达、空原因拒绝、验收归档、装配场景往返和返回画面。工单与场景切换使用 UGUI 事件和实际场景加载，未使用系统鼠标重跑整套工单。既有 NavMesh 初始化提示仍出现在日志中，业务小车实际到达通过。
