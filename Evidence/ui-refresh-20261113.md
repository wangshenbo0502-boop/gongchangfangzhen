# UI 精简、黑灰黄主题与流程验证

日期：2026-11-13，Asia/Shanghai。场景：WorkshopDemo.unity。用户要求精简按钮、简化实训流程，并使用黑色/灰色为主、黄色点缀的工厂实训主题。

## 实现

- 三个一级工作空间：车间总览、设备学习、实训任务。AI 助手在顶部，资料管理在“更多”，小车装配与复盘在实训任务内。
- 首页压缩统计高度，视口保留设备选择、总览和视图；设备卡保留主操作和更多。正常设备查看结构，存在活动告警时主操作进入对应工单。屋顶/跟随归入视图，手动接管/恢复自动归入巡检控制。
- 设备工作区分观察、拆装、故障演示。观察默认隐藏故障时间轴、部件侧栏与近景，拆装模式才显示拆装工具；完整的视角、标注、部件、导出与支持的独立展示器入口保留在菜单中。
- 故障页由六个并列动作减为开始实训/继续处理、查看演示、深入分析三个动作。新建故障后直接进入对应工单，继续使用原有实际到达、维修、验收业务规则。
- 报修现象预填当前教学故障现象并允许修改；本次会话复用已填写的报修人、部门与维修人。原因、维修措施和验收结论仍由使用者填写。
- 有限元分析使用单一结果选择器和基准/缺陷选择，默认收起专业工具；显示、剖切与变形、观察与测量、载荷与导出、模型说明集中到工具抽屉。滑条按相关功能显隐。
- 黑灰底色、黄色导航/主操作、灰白正文；设备列表选中使用暗底，降低大片黄色。场景 UI 标签改为灰色/黄色，分析结果色标保留其物理含义。Esc 关闭最上层菜单/工具/窗口。

主要实现：WorkshopUI.Compact.cs 及 WorkshopUI 原有分部文件；WorkshopSceneOverlay 仅调整 UI 配色。业务状态仍由 WorkshopSimulation / WorkshopDevice 提供。未重建场景或修改模型、拆装路径。

## 本次实际验证

最终检查版分别以 1280×720 和 1920×1080 Windows Player 运行，两组各 179 项 PASS：

- [720p 原始报告](ui-refresh-20261112/delivery-720-20261113/verification.txt)
- [1080p 原始报告](ui-refresh-20261112/delivery-1080-20261113/verification.txt)

方法：显式 `-workshop-ui-verify <目录>` 安装验收组件；正常启动不安装。检查可见 UGUI 控件顶层射线并发送点击/值变更事件。自动验收关闭 InputSystemUIInputModule，避免桌面物理点击干扰；不等于系统鼠标端到端测试。每次操作间保留 UI 刷新时间。

覆盖：主导航和首页工具、四类设备打开、泵 12 总成拆开/回装目标、故障播放、单一结果选择器、基准对比、专业工具、剖切滑条显隐、渐进开裂与返回静态场、故障直接进入工单、报修/派工/小车实际到达/维修/验收闭环、手动与自动模式切换。检查期间无运行时异常。

已人工查看实际 Player 的首页、设备模式、故障页、分析默认界面、工具抽屉及维修页截图。最终截图集中在上述两份报告同目录，文件编号 01–10。

未复跑全部 16 组故障、完整 15 步官方装配训练、实际键盘 H/M/Esc、手动驶离、AI 在线问答及独立展示器启动。既有启动日志中的 NavMesh 代理初始化提示和联网提示仍存在，不能称为零日志错误。自动验收的业务小车实际寻路到达通过。

早期隐藏窗口截图为黑图，不计入视觉验收；初版自动检查在界面显隐同帧立即点击而失败，后续增加等待。第一次 1080p 检查受到外部页面切换干扰，之后隔离桌面输入并重新通过。早期失败记录保留。
