# WorkshopPlatform UI 交互整理方案

日期：2026-11-12（Asia/Shanghai）。状态：规划建议，尚未实施。

对象：`Build/WorkshopPlatform/WorkshopPlatform.exe`。本次检查 README、当前 UI 与业务源码、2026-11-11 平台布局记录及截图、2026-11-12 风机交付记录及截图。没有启动 EXE 重新进行鼠标体验验收；历史截图与当前工作区源码可能存在版本差异。工作区已有用户修改，本次仅新增规划文档。

## 1. 判断与目标

主要问题是把不同任务、不同频率和不同阶段的操作同时呈现。应按“看车间 → 看设备 → 做实训”组织，保留功能，通过任务分层减少同屏选择。

当前源码中首页有 7 个业务导航、1 个装配入口、2 个全局操作、5 个视口按钮、4 个设备操作、1 个驾驶按钮，合计 20 个 Button，另有设备下拉。该数字是创建逻辑清点，不是本次运行测量的可见数量。

整机窗口包含 9 个顶部动作、7 个底部动作、返回按钮，加每个总成的选择行、开关和滑条；拆装与损坏演化同时占用界面。用户需要先辨认操作属于哪件事，才能开始使用。

具体问题：

- 导航把 AI 问答置于首位，默认落在模型展示，视觉优先级与主任务不一致。
- 新建故障课题、重置在每页常驻，与阅读资料、看模型等任务无关。
- “设备档案”跳到整个设备台账；台账行又跳回三维首页，没有形成当前设备详情闭环。
- “整机拆装”和“详细展示”缺少差异说明，后者实际启动另一个程序，且目前仅泵、风机受支持。
- 从首页打开整机窗口仍显示“返回工况”，与实际来源不一致。
- 主界面固定占用大块统计区、侧栏与趋势区，三维观察空间不足；把文字整体缩小不能解决问题。

## 2. 信息架构：三个一级入口

| 一级入口 | 核心任务 | 收纳内容 |
| --- | --- | --- |
| 车间（默认） | 看状态、定位异常、跟进巡检 | 三维现场、设备选择、紧凑统计、告警、机器人状态 |
| 设备 | 了解结构与运行信息 | 四台设备和小车目录、档案、观察、拆装、故障演示 |
| 实训 | 选课题、执行步骤、复盘 | 故障课题、维修工单、小车装配训练、历史复盘 |

全局辅助入口：右上角“AI 助手”“更多”。AI 打开侧边抽屉，保留当前设备/工单上下文；更多内放资料管理、声音、帮助。知识导入归入资料管理；重置仅在实训会话菜单中提供。

三个一级入口是最终建议。可先在现有 UGUI 上迁移入口和显隐，再整理内容，避免一次性重写全部页面。

## 3. 车间首页

布局：顶栏三项导航 + 一行简短统计 + 大面积三维现场 + 可收起的设备详情 + 底部机器人状态。取消高大的四张 KPI 占位；数字仍可读，告警数可打开告警列表。

- 视口常驻：设备选择器、回到总览、视图菜单。屋顶显示、跟随小车放入视图菜单，并明确当前开关状态。
- 点选设备只选择和更新详情；双击设备聚焦。通过告警定位则允许直接聚焦异常设备。设备选择与镜头行为需一致。
- 未选设备时详情收起；选中后显示名称、运行状态、2–3 个与该设备相关的指标。趋势、参数和档案放到可展开的详情区。
- 正常设备主动作：“查看设备”；更多操作中提供启停。设备存在告警时主动作改为“处理告警”，次动作仍保留查看设备。
- 处理告警必须定位到所选设备的活动工单；若只有其他设备告警，则通过告警列表进入，不能错误绑定。
- 小车状态条显示待命/途中/已到达/手动接管；点击展开巡检控制。手动接管、恢复自动放在这里，模式切换后持续显示当前模式与方向键提示。
- AI 抽屉与大设备详情在窄屏时互斥展开，关闭后回到原详情；不能两侧挤压现场。

首页默认态目标：3 个一级导航、2 个全局辅助入口、2 个视口动作，共 7 个常驻按钮，另有设备选择器和状态入口。选择正常设备后详情最多增加 2 个动作；展开的菜单/抽屉另计。该数是设计预算，尚待原型验证。

## 4. 设备页面：观察、拆装、故障演示分开

设备目录保留水泵、储罐、风机、控制柜、小车；进入设备后保持同一设备上下文。小车观察与原装配训练有清楚区别，不假定它具备四台受监控设备的指标与工单。

| 模式 | 常驻操作 | 按需展开 |
| --- | --- | --- |
| 观察（默认） | 复位视角、视图菜单 | 正/侧/俯视、自动环绕、参数、部件目录、独立展示器 |
| 拆装 | 拆开/装回主按钮、上一步、下一步、进度 | 部件目录、标注、视图菜单 |
| 故障演示 | 工况选择、播放/暂停、时间轴 | 起裂等时间标记、损坏近景、分析参考、保存/导出 |

拆装设计：整机状态按钮为“拆开”，展开状态为“装回”；运动中显示运动方向与“暂停”，暂停后显示“继续”，反向动作作为明确次操作，不让同一个无提示按钮突然切换含义。增加暂停能力需改运动控制，不能只改按钮名称。步骤按目标/完成状态锁定，避免快速点击跳过合法顺序。

故障演示设计：把“完好、起裂、最终”变为时间轴标记；复播放在播放附近。近景仅在故障演示且有有效目标时出现；观察和拆装默认不占用右上角。演示预览不应自动注入车间故障，正式触发从实训课题执行。

“整机拆装”“整机与演化”统一导向相同设备工作区，但分别打开对应模式。“详细展示”改为“在独立展示器中打开”，仅能力和配套文件均满足时出现；启动前即表明会打开新窗口。当前泵/风机支持情况以部署能力为准，不因控制柜/储罐存在独立审看工程就承诺已接入。

有限元窗口改称“分析参考”，由故障演示进入；用“显示量”选择应力/位移/温度，基准/缺陷为对比选项，测点/导出收纳到工具菜单。保留参考数据和预设演化的边界说明，不暗示实时求解。

## 5. 实训页面：按阶段给下一步

首页展示“故障处置”“小车装配”两类任务；复盘作为次级标签。新建故障课题仅在此出现，课题选设备、工况后进入执行页；复用现有报修/派工/维修/验收条件。

| 业务阶段 | 主按钮或主要反馈 | 约束 |
| --- | --- | --- |
| 未选课题 | 开始实训 | 选择适用设备与工况 |
| 待报修 | 提交报修 | 填报修人、部门和现象 |
| 待派工 | 派发巡检 | 填责任人/时限，检查小车占用与可达路径 |
| 巡检途中 | 显示行进状态，提供跟随 | 不能提前提交维修 |
| 已到达、待维修 | 提交维修 | 填原因、措施、材料；离开维修点撤销许可 |
| 待验收 | 验收通过 | 驳回重修为次操作，需意见 |
| 已关闭 | 查看复盘 | 清故障并按既有逻辑恢复故障前启停状态 |

只显示当前阶段的表单；阶段条说明已完成、当前与后续步骤。空工单列表提供“开始故障处置实训”入口，不呈现无法提交的空表单。小车被另一单占用时显示目标设备及原因。

“结束并重置本次实训”放入会话菜单，确认中写明清空本次告警/记录并恢复设备与小车；取消保留当前上下文。这个确认是产品设计，非本次执行申请。

小车原装配训练保留现有场景与 15 工序逻辑，仅统一入口及返回。跨场景会话状态是否能恢复必须检查，不能先承诺返回时工单/镜头均完整保留。

| 有限元分析、导出测点 | 分析参考及其工具菜单 |
| 保存画面、导出尺寸 | 当前工作区的导出菜单 |

## 7. 操作与视觉规则

1. 每个任务区域最多一个高强调主动作；普通导航、视角和导出不使用同等级高亮。
2. 常用动作直接可达，低频动作最多再展开一层；不得把所有按钮塞进一个无限增长的“更多”。
3. Esc 关闭最上层菜单/抽屉/弹窗，再返回上层；输入框编辑和存在未提交表单时需处理草稿，不可误清空。H、M 继续保留，输入文字时不触发。
4. 同一场景切页保留选中设备、当前工单、相机和表单草稿；助手也显示当前上下文。跨场景另做生命周期处理和验证。
5. 长操作反馈加载/播放/派发状态，防止重复点击。不可操作时明确原因，不能只留下无说明的灰色按钮。
6. 状态用文字配合颜色；危险操作、告警与普通强调区分。保留“本地模拟”标识。
7. 1920×1080 与 1280×720 分别布局：窄屏收起详情/部件目录，少用横排按钮；不得靠等比缩小所有字体解决。正文建议实际屏幕 14–16 px、主要命中区约 40 px 起，最终以 Unity 实际缩放后的可读性验证。

## 8. 分步实施与验收

**第一批：优先减负。** 首页导航收敛、统计压缩、工具菜单、设备详情显隐；移走全局故障/重置；修正返回来源与名称。拆装窗口先分三种模式、隐藏无关工具。复用现有业务接口，暂不新增复杂运动能力。

**第二批：任务顺序。** 设备工作区统一入口、实训步骤页、AI 抽屉、资料管理；处理草稿、相机、设备上下文及跨场景返回。补拆装暂停/继续时验证运动边界。

**第三批：运行验收及交付。** 在实际 Windows 构建中测试鼠标/键盘、两分辨率及业务闭环，确认后更新日常 EXE 与 README，记录新 Evidence。保护整个现有 Viewers 交付，尤其 `Build/WorkshopPlatform/Viewers/WaterPumpViewer/`，不清理或覆盖它。

建议实现位置：`WorkshopUI.cs` 负责导航及工作区布局；`WorkshopUI.Equipment.cs` 负责设备模式与工具；`WorkshopUI.Analysis.cs`、`WorkshopUI.Fracture.cs` 负责分析工具收纳；`WorkshopUI.ReviewedViewer.cs` 提供能力与配套文件检查；`WorkshopUI.Integration.cs` 统一输入和返回。页面状态使用命名枚举替代到处散落的页码，业务状态继续以 `WorkshopSimulation` / `WorkshopDevice` 为准。检查生成配置的一致性，不调用整场景覆盖重建作为 UI 修复手段。

验收目标（待实施后执行）：

- 首页按钮数按上述预算实测；菜单折叠后无隐藏面板遮挡三维点击。
- 首页到选定设备拆装不超过 3 次点击；从选定设备告警到相应工单不超过 2 次；常用功能不因收纳而难找。
- 两分辨率无文字截断、重叠或横向溢出；鼠标、滚轮和相机输入互不抢占。
- 四台设备、16 组现行故障组合，以及报修→派工→实际到达→维修→验收/驳回闭环回归；历史 32 组测试不能替代现行目录。
- 手动驶离撤销维修权限、恢复自动继续任务，人工停机恢复逻辑及多告警/小车占用仍正确。
- 泵 12 总成、风机 11 总成拆装及中途操作回归；路径、材质与模型保持既有批准版本。
- H/M、Esc、输入框焦点、同场景上下文、跨场景返回分别验证；官方装配与自研监控分开记录。
- 独立展示器存在/缺失和已打开情形、助手离线与恢复都有可理解反馈；服务成功历史不等于本次真实问答通过。

本次完成：源码与历史证据核对、交互方案和布局草图。未修改 Unity 源码、场景、模型、EXE 或既有验证报告；未执行构建或运行验收。
