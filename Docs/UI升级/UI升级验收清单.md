# UI 升级实施验收清单

日期：2026-11-14。配合 [UI 升级指导书](../../UI升级指导书.md) 使用。**这是后续实施的检查模板，所有未勾选项目均不代表通过。本次只编写文档，不执行这些检查。**

## 1. 设计评审

- [ ] 总览、设备工作区、工单三张核心页面使用同一套色板、字体、圆角和间距。
- [ ] 静态稿注明“设计方案”；运行截图注明场景、分辨率和采集时间。
- [ ] 同一工作区的主导航、页签、主操作、次操作能从外观上区分。
- [ ] 同屏突出一个当前主操作，黄色不大面积铺满导航和所有按钮。
- [ ] 设备名称、状态、数值、单位分别形成层级。
- [ ] 模型或三维车间占据主要展示面积，装饰不抢占工作区域。
- [ ] 保留“本地模拟”和必要的教学/结果来源说明。
- [ ] 设备封面与实际模型一致，四张封面的背景、角度和布光统一。

## 2. 分辨率与文字

每个主要页面至少检查 1280×720 与 1920×1080；扩展检查 1600×900、2560×1440 及可调整窗口。

- [ ] 中文无缺字、乱码、意外假粗体；编号、温度符号、立方单位能正确显示。
- [ ] 实际屏幕上的关键正文清晰，缩放后不会只剩很小的注释文字。
- [ ] 按钮文字、状态文字和下拉选项没有截断；长设备名和长故障名有明确处理方式。
- [ ] 下拉菜单位于屏幕内，长列表可滚动，选中项可辨认。
- [ ] 长工单和长回答可以完整滚动查看；滚动内容不会覆盖固定操作区。
- [ ] 详情面板与视口互不遮挡；窗口变化后没有残留边框或空洞。
- [ ] 数值更新不会使单位、按钮或同列文字持续左右跳动。
- [ ] 错误提示和禁用原因可读，不只通过颜色表达。

## 3. 交互与焦点

- [ ] 所有可见按钮实际可点击，装饰图、透明面板和标签没有挡住事件。
- [ ] 悬停、按下、选中、禁用有一致反馈；键盘焦点可辨认。
- [ ] 输入框聚焦时 H、M 等快捷键不会干扰输入。
- [ ] 点击 UI 不会误选或旋转后方三维对象。
- [ ] 点击视口空白处、设备标签与设备模型的行为符合设计。
- [ ] 打开/关闭菜单和弹窗后，原页面仍可交互；Esc 按当前层级返回。
- [ ] 隐藏/恢复 UI 后，场景相机视口、标签投影和点击坐标一致。
- [ ] 从小车装配返回车间后，无原场景画面残留、错位或焦点失效。
- [ ] 至少用真实鼠标执行一遍关键流程，不能只用按钮事件调用替代。

## 4. 总览与设备学习

- [ ] 显示当前四台设备及原巡检小车，统计来自现有业务状态。
- [ ] 设备目录、场景点选、空间标签、右侧详情保持同一选中设备。
- [ ] 启停操作会更新设备动画、状态、统计与详情；故障不能通过普通启停解除。
- [ ] 储罐和控制柜的转速/振动没有伪造读数；适用指标正确。
- [ ] 温度曲线读取实际模拟采样，切换设备和重置后无旧数据混入。
- [ ] 曲线单位、范围和刻度与实际绘图一致；数据不足、无选中设备有合理反馈。
- [ ] 四类设备的观察、旋转、缩放、复位、拆装、装回入口保持可用。
- [ ] 模型总成数、拆装路径、材质、灯光与既有交付的变化分别说明。
- [ ] 故障演示与观察模式切换后，正确恢复相应设备模型。
- [ ] 独立展示器入口仍可用，受保护水泵展示器及其配套文件未被破坏。

## 5. 工单业务闭环

- [ ] 选择设备和故障后，进入对应工单，设备名称自动带入。
- [ ] 重复创建同一未处理设备故障受到既有规则限制。
- [ ] 派发后小车沿实际可达路径移动；忙碌或不可达时有明确提示。
- [ ] 途中“查看现场”和“返回工单”回到同一个任务上下文。
- [ ] 小车未到场时，不能通过 UI 提前提交维修。
- [ ] 小车实际到场后才能进入维修；空原因被拒绝，错误靠近输入区域。
- [ ] 维修提交后进入待验收，设备故障仍保留。
- [ ] 验收通过后归档并更新统计，设备恢复故障前应有的启停状态。
- [ ] 驳回后回到真实业务阶段，进度条同步回退。
- [ ] 多设备并存告警时，工单、选中设备与机器人目标没有混淆。
- [ ] 手动接管、离开维修点、恢复自动按既有规则工作，不因 UI 显示保留错误许可。
- [ ] 重复点击不会重复提交或产生重复归档记录。
- [ ] 连续重置两次后状态干净，再执行一轮完整流程仍能完成。

当前 README 说明四台设备共 16 组可操作故障组合。后续实施时应核对当时的 `WorkshopFaultCatalog`；若 UI 改造覆盖故障菜单与状态展示，应逐组检查可选项与界面表现。历史八设备/32 组合验证不能直接套用。

## 6. 助手、资料与专业结果

- [ ] 助手显示当前设备和工单阶段，提问使用正确上下文。
- [ ] 等待、成功、无引用、离线、鉴权失败、普通请求失败有对应显示。
- [ ] 长回答、引用展开和连续追问不遮挡输入区。
- [ ] 文档导入、处理、成功与失败的状态区分清楚，列表状态以实际结果为准。
- [ ] 有限元结果类型、单位、图例和数据来源保持准确。
- [ ] 参考算例、教学示意和真实外部结果明确区分，不能靠换皮扩大能力声明。

## 7. 原小车训练场景

- [ ] 组装/使用、远景/近景切换可用。
- [ ] 引导提示、继续、自动示意、重置、完成统计可读且可操作。
- [ ] 部件拖装、机械臂滑条和相机输入没有被 UI 遮挡。
- [ ] H 隐藏界面、M 静音与监控场景保持约定一致。
- [ ] 训练场景单独记录验证结果，不以车间总览检查替代。

## 8. 性能与交付

- [ ] 同一机器、分辨率、场景和状态下记录改造前后帧时间与内存；没有把独立展示器历史性能当作主平台本次结果。
- [ ] 新图片尺寸合理，无大量未使用的大图和重复背景导入。
- [ ] 新资源来源、用途、授权记录齐全，`.meta` 保留。
- [ ] 没有擅自重建覆盖 Demo 场景、替换渲染管线或修改官方资源。
- [ ] 检查版与正式版的路径明确，正式替换按届时用户指令处理。
- [ ] 功能或入口改变后更新 README，验证写入新的 Evidence 文件。
