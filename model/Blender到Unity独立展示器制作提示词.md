# Blender 到 Unity 独立展示器制作提示词

更新日期：2026-11-12。默认设备改为**电气控制柜**，结合离心泵与轴流风机的实际交付、穿模修复及动画性能验证完善。

这是后续制作的任务模板。编辑本文件不代表执行其中的导出、构建或平台替换，也不代表控制柜外观已经验收。当前控制柜仍处于 Blender 评审阶段；水泵、风机已各自提供独立展示器并接入平台。

## 使用方法

将下方提示词整段交给执行助手，并说明本次授权范围。默认先完成第一至第三阶段，直接交付可运行的独立 EXE 供用户验收；用户验收满意并要求接入项目后，再执行第四阶段。

| 阶段 | 工作范围 | 阶段产出 |
| --- | --- | --- |
| 第一阶段 | 源模型核对、重新导出、坐标与层级回读 | 经检查的新 FBX、材质和运动配置 |
| 第二阶段 | 隔离 Unity 工程、材质、开门拆装与交互、性能优化 | 可构建的独立展示器工程 |
| 第三阶段 | Windows x64 构建、真实交互与性能验证、截图 | 完整 EXE 目录及验收证据 |
| 第四阶段 | 用户验收并授权后替换平台控制柜、部署入口 | 平台模型、详细展示入口及回归记录 |

源文件版本、路径和统计以执行时的最新文件及专项记录为准。用户后续明确指令优先于模板；不要重复索取已有授权，也不要因文档写有后续计划就自动执行第四阶段。换设备时须同步修改标识、路径、总成和运动约束，不能仅替换设备名称。

本次拟新建的独立输出（不是已完成交付）：

【先检查，保护已有工作】
1. 先读根目录 README.md、AGENTS.md、控制柜最新报告、相关专项记录及
   导出构建参考，检查 Git 状态。保留用户修改、资源、场景及 .meta。
2. 默认只读审核源文件。需要修模型或运动时，先保存可追溯修订副本，
   记录差异；不要运行基础建模脚本覆盖最新布线、器件壳体和贴图。
3. 当前源模型基线为 16 总成、3,230 网格、109,824 三角面；
   宽×深×高约 1.208147×0.655000×2.000000 m，根节点
   electrical-cabinet 位于底面中心。执行时重测并解释差异，
   不把历史统计硬编码为所有后续版本的断言。
4. 当前源检查通过不等于 Unity 导入、动态净空或电气回路已经通过。
   已记录的 183 条路径没有完整电气网表，门运动线束尚未验证。
   不宣称电气选型、回路连通或安全认证；HMI 内容保持演示属性。
5. 若没有新的外观认可或直接转 Unity 指令，先说明现有审图状态；
   已有明确制作授权时按授权继续，不凭历史“待审”反复要求确认。

【第一阶段：导出、坐标与数据契约】
1. 从最新源模型 01_ASSEMBLED 的闭门组装初始帧导出。只包含设备根、
   必要 Empty、总成和设备网格，排除摄影棚、地面、灯光、相机及其他
   Scene 的重复对象。单位米，保留 UV、材质槽、法线和真实铰链枢轴。
2. 控制柜保留以下 16 个稳定总成，不强行凑八组，也不超过 16 组：
   CAB_00_Enclosure          柜体框架及安装结构
   CAB_01_Backplate         安装背板及附件
   CAB_02_Terminals         端子排及 PE 排
   CAB_03_Door              柜门、锁及铰链
   CAB_04_Breakers          进线及支路保护器件
   CAB_05_PLC               PLC 与 I/O
   CAB_06_Cooling           通风散热组件
   CAB_07_Wiring            线槽、线束及标记
   CAB_08_ControlPanel      固定操作条及按钮
   CAB_09_PowerSupply       24 V 电源组件
   CAB_10_PlinthGlands      底部进线格兰及附件
   CAB_11_Contactors        接触器及热过载组件
   CAB_12_VariableSpeedDrives 变频器组件
   CAB_13_IndustrialNetwork 工业网络组件
   CAB_14_SafetyRelays      安全及接口继电器
   CAB_15_OperatorHMI       门板 HMI 组件
   每个设备网格恰好归属一个总成；紧固件、标识和插接件跟随所属器件。
   不依赖易变化的网格序号、显示名排序或水泵/风机固定索引。
3. 新建控制柜专用导出脚本。FBX 可参考 Up Y、Forward -Z、scale=1，
   默认不烘焙动画，但参数是否适用必须回读确认。不要一刀切 Apply
   铰链变换；不要未经验证开启 bake_space_transform。
4. 随 FBX 导出不参与渲染的原点及 X/Y/Z 单位轴参考节点。
   Unity 从实际导入结果求源坐标到设备局部坐标的变换，检查轴长、
   正交性、手性、尺寸、前向和开门方向，不能硬写猜测的轴转换。
   风机曾因 (x,z,-y) 与实际 (x,z,+y) 不一致导致部件向内穿入。
5. 点、位移、方向、旋转及绕枢轴运动分别正确转换；含反射的基变换
   不能直接当普通四元数使用。核对真实导入后的门边、铰链和外退方向。
   所有运动统一定义坐标空间，只转换一次，避免父子重复变换。
6. 输出版本化 parts.json / materials.json 及导出清单，至少记录：
   源文件路径与哈希、工具版本、schemaVersion、motionVersion、
   单位、轴参考、总成稳定 ID、中文用途、网格归属、真实标注锚点、
   初始位姿、枢轴、分段位移/旋转、时长、依赖关系和材质映射。
   使用 Unity JsonUtility 时 Vector3 写成 {x,y,z} 对象，不能写数组。
   导出和运行时共用运动配置，不在导出脚本里偷偷覆盖路径或版本号。
7. 新 FBX 单独回读，再在 Unity 实际导入检查尺寸、层级、材质槽、
   纹理依赖、法线、铰链和组装姿态。源网格数量和优化后渲染网格数
   分别记录；合批需保留原对象到总成的追溯映射。
8. 程序化拉丝、微纹理等不能依靠 FBX 自动还原；按需烘焙或重建，
   校验打包图片、外部贴图和色彩空间，记录新增素材来源及许可。

【第二阶段：独立工程、真实材质与完整交互】
1. 参考 PumpViewerProject 和 FanViewerProject 的已验证实现建立
   CabinetViewerProject，只复制必要源码、Shader、Packages 和设置。
   不整包复制旧项目、Library、Temp、Bee 或旧设备生成资产。
2. 材质按源模型名称持久化映射，区分喷涂钢板、镀锌背板、绝缘塑料、
   铜排、导线护套、橡胶、玻璃、HMI 及标签；保留细微粗糙度和法线。
   不把所有表面刷成一种灰色高光，不整体发白、塑料化或镜面化。
3. 基础色贴图按 sRGB，Metallic/Roughness/AO 等数据按线性处理；
   法线按法线类型导入。按实际 Shader 转换 Roughness/Smoothness，
   核对通道打包，不重复 Gamma 转换，不仅替换 Shader 名称。
   导入有效法线，按需使用 MikkTSpace 切线，近看核对方向和强度。
4. 中性工作室、HDR 反射和适度主辅光，保留接触阴影；对照 Blender
   同部位校准颜色、曝光及反射。端子井、散热鳍片和接线不能被黑影
   吞掉；按钮不烧白，HMI 玻璃不遮住内容，不出现透明排序黑线。
5. 以已认可的 HDR、4× MSAA、renderScale=2、原分辨率贴图、
   各向异性过滤和轻度锐化为画质参考，实测后确定控制柜设置。
   renderScale=2 意味着约四倍像素成本；优化先测瓶颈，不默认降质。
   不用景深、运动模糊或过强锐化掩盖问题；近看端子号、铭牌、
   PLC 印字、细线和门边，检查压缩、闪烁、摩尔纹及文字清晰度。
6. 保持简洁操作区，主要按钮为“拆解、组装、部件简介”，不添加可见
   时间线、播放暂停和调试参数。拆解先完成开门，组装末段再关门；
   如需独立开门入口，沿用同一状态机，避免多套动画同时争用。
7. 运动必须根据结构设计分段和依赖：先解除遮挡及连接，再向柜外
   退出，完全脱离门框、操作条、导轨和线槽后再分散。背板不穿后壳，
   格兰不穿底板，器件不斜着穿过柜门或相邻组件。不要把历史 OFFSETS
   直接当已验证的 Unity 拆装路径，不让全部器件同时直线飞散。
8. 门铰链历史 Blender 坐标为 (-0.574,-0.279,0.160) m，绕源 Z
   开启 -100°；仅作核对线索，须从最新模型和实际 FBX 重测。
   CAB_03、CAB_06、CAB_15 在历史配置中随门转动，导入后按实际
   安装归属核验；HMI 独立分组但仍随门开合，不能重复叠加门变换。
   CAB_08 是固定操作条，不是整扇门，不应随门开合。
9. 门接地软线、HMI 线及跨总成连接须有明确归属和连接状态：
   开门保持合理弯曲余量，不能把硬线拉长或带着线槽一起转；
   拆解时先表现连接解除，再移动器件，组装逆序恢复。可在原总成内
   用附属节点驱动，不额外增加总成；不要靠隐藏穿模来冒充净空。
10. 使用统一时间线、自然缓入缓出和机械顺序，组装严格反向复现。
    参考水泵/风机约 14 秒单程，按柜体步骤调整，不靠加快动画藏问题。
    动画中反向或连续点击从当前进度平滑接续，不瞬移、不叠加协程。
    多轮归位后位置、旋转、层级、连接与开关状态准确复原。
11. 整机、开门、全拆和内部近看均应可观察；04_INTERNAL 中移开固定
    操作条属于观察示意，不能表现为设备运行中的真实机械动作。
    不照搬风机叶轮转动，故障演示只使用有依据的屏幕/灯光状态。
12. 支持 360°旋转、缩放和必要平移。相机范围覆盖开门与全拆包围盒，
    不裁切、不钻入模型。运动中缓存几何范围，不每帧重扫全部网格。
13. 完全拆开后双击实际部件选中整个总成，保留原材质并显示细白轮廓。
    选取依据实际几何及归属映射；单击、拖动、UI 点击和动画期间
    不误选，螺丝不各自变成一个装配步骤。
    简介包含中文名、一两句用途和结构说明；未选中时给出合理入口。
    标签使用近距离短引导线，避开屏幕边缘、操作区及彼此重叠。

【第二阶段的性能要求：高清且运动平稳】
1. 控制柜有 3,230 个源网格，不能只看三角面数判断性能。测 CPU/GPU、
   Draw Calls、SetPass、显存和分配，优先处理实际瓶颈。
   可在同一总成、同一材质且运动一致的范围内合批；保留铰链、
   独立运动件、材质槽、标识、选择映射及可编辑 Blender 源文件。
2. 缓存 Transform、路径采样、总成归属和相机范围。运动循环避免
   GetComponents、LINQ、重复射线遍历、新建材质/碰撞体、资源搜索、
   文件写入和持续 GC；选择遮罩相机仅在实际需要时渲染。
3. 帧率目标参考显示器刷新率整数分频、最高 144 FPS：240 Hz 可取
   120 FPS，144 Hz 可取 144 FPS，60 Hz 可取 60 FPS。
   窗口模式不要假定 VSync 一定限帧；记录实际策略及焦点恢复行为。
   以目标硬件稳定达到至少 60 FPS 为基本目标，高刷能力实测报告，
   不能照搬风机成绩保证控制柜也有 120 FPS。
4. 实际提交高清场景并完成必要预热后再推进运动。立即点击应被保留，
   就绪后自动执行；准备状态清楚、等待有上限，不丢点击或无限等待。
   风机的“连续 6 帧稳定、最多等待 3 秒”仅是参考，控制柜单独测量。
   启动等待和运动时长分别记录，不能把等待算成流畅运动。
5. 独立保留“完整导出/资源生成构建”和“仅运行时代码增量构建”。
   脚本修复不重复重建模型、材质和 .meta；不遗留双份 Shader、
   旧设备逻辑、摄像机或多个互相争用的更新循环。

【第三阶段：构建 EXE、实际验收与交付】
1. 编写控制柜专用、可重复执行的导出、构建和验证脚本；记录源哈希、
   配置版本、工具版本、时间和输出。构建失败保留日志及旧可运行版。
   交付整个 Windows x64 目录，含 EXE、Data、UnityPlayer 等依赖。
2. 从 model/CabinetViewer/CabinetViewer.exe 实际启动验证。
   至少覆盖 1920×1080、1280×720 及本机实际较大窗口；
   记录系统缩放、显示刷新率、硬件、图形 API 和画质设置。
3. 验证闭门、开门、全拆、内部近景、旋转缩放、全部 16 总成选取、
   描边、简介和标签；检查中文、UI 遮挡、透明黑线及近景清晰度。
   连续多轮拆装、中途反向、快速点击及最终归位都要测。
   脚本调用 Button.onClick 不等于真实输入，需覆盖普通鼠标操作；
   报告区分操作符/代码驱动、OS 鼠标驱动和人工目视检查。
4. 净空检查覆盖实际 Unity 导入模型的开门、退出、侧移、回装及关门，
   对路径折点、临近接触和换段处加密采样，并从多个视角审看。
   重点检查门/HMI/冷却件、固定操作条、器件/线槽、背板/柜壳、
   底部格兰和门接地线。连接处允许接触的对象及容差须单独说明。
   AABB 重叠只作粗筛，不能直接认定穿模；离散网格检查也不等于
   连续运动证明或制造级干涉认证，写清采样、排除项及未测范围。
5. 冷启动立即点击、首次完整拆装、重复拆装、中途反向分别测帧时。
   报告平均 FPS、P95/P99、最慢帧及超过 16.67/25/33.33/50 ms
   的帧数、主线程分配和 GC。先设目标帧预算，再依据结果修复。
   测量段不截图、不写日志文件、不删慢帧；记录启动等待和实际
   运动起止。目标为运动无持续明显卡顿、无周期性 GC，异常逐项解释。
6. 历史柜门净空只采了 31 个姿态、部分主要移动/固定网格，
   不覆盖完整门附件和动态线束；源布线通过也不替代拆装净空。
   当前 172 个槽内末端的遮挡抽查不等于所有角度不可见，
   电源负向回归的 pass=false 是预期检错，不能误报为源文件失败。
7. 输出 3–4 张真实 Player 效果图：闭门前侧、开门内景、完全拆开、
   端子/电源/PLC 近景；另留危险换段的中间帧证据。
   截图标明来源，不以 Blender 图或生成图冒充 Unity 实机。
8. 保存导出/构建日志、交互与性能 JSON、截图以及 Evidence 专项记录。
   明确区分代码实现、本次通过、历史通过、用户待验收和未验证。
   不把零异常或构建成功当成视觉、输入、穿模和性能全部通过。
