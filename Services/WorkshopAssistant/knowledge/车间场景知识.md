# 场景定位与数据边界
工业车间设备三维可视化监控与交互巡检系统是 Unity 6 教学演示项目。统一程序 WorkshopPlatform.exe 默认进入 WorkshopDemo.unity，可从“小车装配训练”切换到原 Factory Training 场景，再返回数字孪生平台。左栏包含 AI问答、模型展示、故障分析、设备台账、维修工单、实训复盘、知识导入。全部运行参数由 WorkshopSimulation 和 WorkshopDevice 本地模拟，不是传感器采集。不能把官方训练验证通过当作监控系统验收通过。没有真实 PLC、OPC UA 或 MQTT 设备接入。助手只提供解释和操作建议，不执行设备控制。

# 设备台账
生产车间 A 展示共 5 个模型：巡检小车，加上 P-01 循环水泵（离心循环泵）、TK-01 工艺储罐、F-01 车间排风机（轴流风机）、PLC-01 设备控制柜四台受监控设备。小车负责导航与装配实训，不计入四台设备的运行率。储罐、循环泵和控制柜组成靠近仓库作业侧的工艺设备岛，风机位于设备岛外侧，中央下方保留小车检修通道。设备状态为运行正常、已停机或具体故障名称。静态台账不能证明当前状态，当前状态以请求中的场景快照为准。

# 模拟指标
系统约每 0.25 秒采样一次。水泵、风机正常温度在标称 42°C 附近平滑波动；储罐约 25°C，控制柜约 32°C。正常振动约 1.2 mm/s；风机标称转速 980 r/min，水泵 1450 r/min。故障温度、振动与转速依具体工况变化，不能把所有故障解释成超温。预警工况可降速运行，严重工况联锁停机；人工或故障停机后的转速与当前振动为 0。储罐与控制柜不适用转速、振动。泵有出口压力、流量，罐有压力、液位，柜有控制电压、通信质量；只解释设备适用的指标。以上为教学设定，不是工业报警阈值。

# P-01 超温告警
点击“新建故障课题”打开设备与故障选择窗口，再点击“注入故障”。P-HOT 为泵超温保护，模拟温度约 92°C、保护停机，当前转速和振动为 0。当前泵模型为 P-01；其余三类设备也各有适用故障。每台设备最多一个未处理故障，重复注入受到保护；不同设备可同时告警。ALM-xxx 告警包含对应故障编码、名称、级别和进度。运行数量由实际状态计算，预警不一定减少运行数。

# 多类型故障目录
当前四类设备各有 4 种故障，共 16 个可操作工况。水泵：超温保护、汽蚀、机械密封泄漏、轴承损伤。储罐：超压联锁、罐体泄漏、高液位预警、支座变形。风机：叶轮不平衡、风道堵塞、轴承抱死、叶片裂纹风险。控制柜：柜内散热失效、控制电源欠压、现场总线中断、接点过热。源码仍保留旧输送线和电机目录及对应参考算例，不能据此声称当前车间还展示这些设备。故障机理是预设教学条件，不是自动诊断结论。处理建议以快照告警的 action 为准。

# Abaqus 结果与教学特效
热流线、振动环、漏液、变形轮廓、电气闪烁和堵塞标记均为三维示意，不是应力云图或真实流体计算。可导入真实 Abaqus ODB 导出的指定设备、指定故障、指定实例的时间包络 JSON，回放最大 Mises 应力、最大位移或最高温度。各极值可能来自不同节点或单元，不能当成同一测点，也没有空间网格映射。没有通过校验的 ODB 文件时只运行教学故障模型，不能称为完成 Abaqus 求解。通信中断和控制逻辑也不是有限元直接求解的故障。

# 巡检派发与处理
演示使用一台巡检机器人和一个活动导航任务，可有多台设备待检。流程为：注入故障 → 维修工单填写报修人、部门、故障现象 → 指定维修责任人及处理时限 → 机器人沿 NavMesh 到达设备 → 填写故障原因、维修措施、配件材料（无更换填“无”）并提交 → 报修人填写验收意见 → 验收通过后清除故障、归档。节点显示待报修、待派工、巡检途中、待维修、待验收、已关闭。维修提交即释放机器人，设备故障仍保留到验收通过。验收驳回回到待派工并增加返工次数，必须重新派工复查。派发后任务绑定，选择其他设备不会抢占任务。只有导航路径完整可达才会出发；途中不能提前维修，重复提交和验收受到保护。

# 无法派发、无法确认处理
无法派发时，先检查是否已经提交报修、是否填写责任人和 1–240 分钟处理时限、机器人是否已有任务，以及目标巡检点是否在完整可达的导航路径上。历史“未派发”含义已拆为待报修与待派工。机器人到达目标且目标工单一致后，才可提交维修。模型展示可“跟随巡检”或“手动接管”，方向键驾驶受 NavMesh 约束；手动驶离维修点会撤销到达状态，返回现场后才能提交。恢复自动模式后继续原任务。设备布局移动后需要同步巡检点并重新烘焙导航；助手不能声称已修复路径。

# 复位与记录
使用方验收通过后工单置为“已关闭”，设备恢复故障前的运行或人工停机状态，实训复盘记录故障编码、名称、告警编号、设备、报修人、维修责任人、原因、措施、材料、验收意见、返工次数和从发生到关闭的时长。闭环时长包含等待与验收，不等于纯维修作业时间。教学验收不代表真实设备已经安全维修。重置演示将清空内存工单和记录、恢复全部设备、清除特效、将机器人送回初始位置。重置、退出及切换场景后业务记录不持久保存；Docker 数据库保存的是知识文档与向量索引。

# 故障参考分析与整机观察
故障分析资源共保留 21 组完好/缺陷 scikit-fem 参考件，其中 14 组对应当前四台设备。支持应力、位移、应变、主应力、温度、热通量、剖切、等值线、测点及 CSV/截图导出。参考件使用名义几何和线弹性或稳态热条件，不是整机实测或 Abaqus 结果。当前 PLC-LOW、PLC-COMM 没有 FEM 参考件。渐进开裂和整机 18 秒损坏演化是预设运动学示意，不是求解得到的裂纹扩展。模型展示的“整机拆装”和故障分析的“整机与演化”可观察当前四类设备、拆分部件、故障近景和尺寸导出。Blender 精细泵源模型尚未替换运行模型。

# 知识导入
知识导入支持标题与正文，以及 UTF-8 MD/TXT 本机文件。服务端按内容哈希去重、分片、向量化并保存资料，可供后续 AI 检索引用。知识库就绪不等于 DeepSeek 密钥有效；本地参考资料不等于在线模型生成的回答。索引不可用、密钥鉴权失败应如实显示错误。

# 场景观察
点击设备台账会选中并聚焦设备，三维点选会同步设备详情。左键拖拽或右键拖拽旋转，滚轮缩放，中键平移；总览恢复整体视角，巡检跟随跟随机器人，屋顶开关控制顶棚显示。设备启停按钮仅改变选中设备；故障设备不能通过普通启动解除，需完成巡检处理流程。

# 场景维护建议
针对泵超温，可在演示讲解中建议检查冷却条件、泵入口堵塞、负载和轴承状态；这些只是常见检查方向，项目没有提供足以确定真实根因的传感器或维修数据。真实设备检修须按现场规程与设备厂家手册执行。不要把模拟温度阈值用于真实工厂控制。
